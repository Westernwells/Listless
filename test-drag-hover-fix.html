🐛 Drag-and-Drop State Management Test

📋 Test Instructions

This test helps verify that both the hover state bug and task highlighting issues after drag-and-drop operations have been fixed.

Open Listless App →

🔬 Test Steps

  1. Navigate to the Listless dashboard (link above)
  2. Create 3-4 test tasks in your task list
  3. Perform a drag-and-drop reorder:
    • Click and hold on a task item
    • Drag it to a new position in the list
    • Release the mouse to drop it
  4. Move your mouse away from all task items
  5. Observe the hover states:
    • Move your mouse over different task items
    • Check if hover effects appear only on the item under your cursor
  6. Check task highlighting/selection:
    • Wait 3-5 seconds after the drop operation
    • Verify that NO task items show selection highlighting
    • Confirm the dragged task remains in its new position
  7. Repeat the test with different tasks and positions

✅ Expected Behavior (FIXED)

  • After drag-and-drop completes, no task items should show hover effects when the mouse is not over them
  • Hover effects should appear only on the task item directly under the mouse cursor
  • Moving the mouse between tasks should show hover effects only on the currently hovered item
  • No "sticky" or persistent hover states on multiple items
  • Task selection/highlighting should be cleared after successful drag-and-drop operations
  • No task items should show selection highlighting after the operation completes
  • The dragged task should remain in its new position without any visual artifacts

❌ Bug Behavior (BEFORE FIX)

  • After drag-and-drop, multiple task items show blue outlines/hover effects simultaneously
  • Hover effects "stick" to tasks that are no longer under the mouse cursor
  • The dragged task and the task that took its original position both show hover effects
  • Moving the mouse doesn't properly clear the erratic hover states
  • Task highlighting issue: ~2 seconds after drop, selection highlight moves from the dragged task back to the task in the original position
  • Selection state becomes inconsistent with actual task positions

🔧 Technical Details

Fix Applied:

  • Added hover state reset mechanism in drag end handlers
  • Implemented CSS classes to disable hover during drag operations
  • Added DOM reflow forcing to clear stuck CSS :hover pseudo-states
  • Coordinated state cleanup between global and local drag contexts
